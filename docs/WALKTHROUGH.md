# Поэтапный разбор проекта

Код собран по согласованным этапам. Для изучения двигайтесь в этом порядке; команды выполняются из корня проекта после генерации ключей.

1. **Каркас.** Откройте родительский pom.xml, четыре application.properties и конфигурацию Gateway. Родитель управляет совместимыми версиями, каждый бизнес-сервис запускается отдельным JAR. Eureka находит адреса по имени сервиса. Проверка: запустите комплект и откройте Eureka.
2. **Данные.** Посмотрите миграции V1 и DATABASE.md. Каждому бизнес-сервису принадлежит своя схема. `version` служит для optimistic locking обычных изменений, блокировка строки номера защищает резервирование. Проверка: приложение не запустится при несоответствии JPA и SQL.
3. **Безопасность.** Изучите TokenService, JwtSupport, UserSecurityConfig, InternalSecurity. Вход выдаёт подписанный JWT, каждый сервис проверяет его самостоятельно. `@PreAuthorize` проверяет роль перед бизнес-методом. Проверка: вызов без токена → 401, создание отеля пользователем → 403.
4. **Каталог.** Изучите HotelCatalog и ReservationService. Сравните эксплуатационное поле available с календарной занятостью. При пересечении дат одновременно проверяется наличие резерва и меняется счётчик внутри одной транзакции. Проверка: `mvnw.cmd -pl hotel-service -am test`.
5. **Бронирование.** Изучите BookingController, BookingSaga и BookingStore. Контроллер извлекает владельца из проверенного JWT, а не из пользовательского тела. Уникальный requestId обеспечивает один результат. Проверка: два одинаковых запроса → один bookingId.
6. **Сага.** Изучите HotelClient и RecoveryWorker вместе с ADR-002/003. HTTP нельзя удерживать внутри транзакции БД. Компенсация нужна даже при неизвестном результате запроса. Проверка: `mvnw.cmd -pl booking-service -am test`; обратите внимание на lost-response и release-before-confirm.
7. **Система целиком.** Изучите SystemIT. Он запускает четыре настоящих процесса и тестовый прокси, который сначала передаёт confirm в Hotel, а затем задерживает ответ. Проверка: `mvnw.cmd verify`; ровно один победитель из 20 и освобождение номера после потери ответа.
8. **Сдача.** Пройдите CRITERIA.md, выполните scripts/demo.ps1. Подготовьте объяснение выбора H2, разделения БД, JWT, локальных транзакций, идемпотентности и блокировок. Перед публикацией проверьте, что ключи и .run не включаются в Git.

На защите полезно показать три сценария: успешная бронь; повтор с тем же requestId; сетевой сбой после резервирования с последующим release. Последний сценарий воспроизводится системным тестом, без добавления аварийных эндпойнтов в продуктовый API.
