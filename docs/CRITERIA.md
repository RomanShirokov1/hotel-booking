# Соответствие критериям оценки

Максимальная сумма в задании — 50. Таблица показывает предусмотренные доказательства; итоговую оценку выставляет проверяющий.

| № | Максимум | Реализация | Проверка |
|---|---:|---|---|
| 1. Планирование | 5 | Рекомендации times_booked/id в обоих бизнес-сервисах, координация автоподбора, блокировки и идемпотентность | HotelIntegrationTest: баланс, соседние даты, 20 конкурентов; SystemIT: 20 запросов на один номер и 12 параллельных автоматических броней на разные даты |
| 2. Согласованность | 5 | Сага, компенсации, Retry/Timeout/CircuitBreaker, tombstone | BookingIntegrationTest; SystemIT: потеря ответа после commit Hotel |
| 3. Booking CRUD | 5 | Создание, история, чтение, отмена, владельцы, пагинация, даты | BookingIntegrationTest; SystemIT |
| 4. Hotel CRUD и статистика | 5 | CRUD отелей/номеров, фильтры, сортировка, занятые ночи и процент | HotelIntegrationTest; SystemIT |
| 5. Gateway и Eureka | 5 | lb:// маршруты, регистрация, JWT на входе, корреляция | SystemIT: четыре реальных приложения и маршруты |
| 6. Безопасность | 5 | Resource Server, @PreAuthorize, BCrypt, роли, аудитории JWT | JwtSupportTest; оба интеграционных класса; SystemIT |
| 7. Полнота тестов | 3 | Ошибки, конкуренция, подтверждение, компенсация, тайм-ауты | mvnw verify |
| 8. Схема данных | 2 | Миграции, индексы, связи, ограничения, дополнительные журналы | Flyway + Hibernate validate; DATABASE.md |
| 9. Предзаполнение | 2 | Два отеля, ремонт, пользователи, прошлые/будущие/отменённые брони | Профиль demo, scripts/demo.ps1, SystemIT |
| 10. Качество кода | 3 | Контроллеры, сервисы, репозитории, DTO/мапперы, интерфейс HotelOperations | Структура модулей и исходники |
| 11. Стиль | 2 | Google Java Format через Spotless | spotless:check входит в verify |
| 12. Ошибки | 2 | Общий ErrorDTO, централизованные обработчики, 4xx/5xx | Негативные MockMvc и HTTP-сценарии |
| 13. Логи и трассировка | 2 | ECS JSON, traceId, bookingId/operationId в событиях, метрики | .run/*.log и system-tests/target/*.log |
| 14. Документация | 2 | README, схема архитектуры/БД, ADR, инструкции модулей | README.md, docs/ |
| 15. Поддерживаемость тестов | 2 | Изоляция данных, WireMock, синхронизация конкурентов, автоматические порты/остановка | Исходники тестов и CI |

Обязательный полный прогон: `java scripts/GenerateKeys.java`, затем `mvnw.cmd verify`. GitHub Actions настроен отдельно; локальный успешный прогон не является свидетельством выполненного запуска на GitHub.
